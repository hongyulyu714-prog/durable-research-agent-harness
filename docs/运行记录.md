# 运行记录与复核说明

## 可重复的离线验收

执行环境：Python 3.11。执行命令：

```bash
PYTHONPATH=src python3.11 -m pytest -q
PYTHONPATH=src python3.11 -m ruff check .
```

结果：`42 passed`，静态检查通过；不使用网络或 API Key。

核心证据在 `tests/test_integration.py`：

| 要求 | 断言与可检查证据 |
|---|---|
| 多轮 loop | 三次 `MockLLM` 回合：读取/网页、提出写入、审批后最终回答。 |
| 真实并发 | `read_file` 与 `fetch_url` 均须在对方开始后才能继续；断言 `tool_batch_completed.duration_ms < aggregate_tool_duration_ms`。 |
| 失败隔离 | `fetch_url` 产生结构化 `network_error`，而 `read_file` 仍成功并进入下一模型回合。 |
| 暂停与审批 | `write_report` 在 `waiting_approval` 前从未执行；批准后才执行一次。 |
| 跨进程恢复 | 新的 `ApplicationService` 与 `StateStore` 实例只读取 checkpoint 并完成恢复。 |
| 完整轨迹 | JSONL 断言含 loop、工具结果/批次、审批、写入和 `run_completed`；摘要记录一次工具失败和一次批准。 |

轨迹只记录运行元数据。`TraceRecorder` 会遮蔽名称中含 `api_key`、`token`、`secret`、`password` 等字段；对内容、正文、参数和工具数据仅记录长度与短哈希。

## 真实 API 运行

本次交付环境未配置 `OPENAI_API_KEY` 和 `OPENAI_MODEL`，因此没有伪造真实模型调用，也没有将离线模拟标为真实 API 记录。在已配置凭据的环境中，可执行：

```bash
set -a; source .env; set +a
mkdir -p demo-workspace/data demo-workspace/reports demo-runs
printf 'A short local source.\n' > demo-workspace/data/source.txt
research-agent --runs-dir demo-runs run \
  "Read source.txt, fetch one public source, and write a Markdown brief." \
  --workspace demo-workspace
research-agent --runs-dir demo-runs resume <run_id> --approve --workspace demo-workspace
research-agent --runs-dir demo-runs inspect <run_id>
```

审阅 `demo-runs/<run_id>/events.jsonl` 与 `summary.json` 后，可在确认不含任务正文、用户资料或访问令牌的前提下保存副本。若批准后的写入已开始但结果尚未落盘，系统会拒绝自动重试，要求先人工检查报告目标。

## 与方案的一致性

当前实现保持方案边界：`AgentLoop` 掌握状态流转；`ToolRegistry` 负责 schema 与参数验证；`AsyncToolScheduler` 负责并发、timeout、重试与失败隔离；`ApprovalService` 与 `StateStore` 负责可恢复审批；`TraceRecorder` 输出脱敏事件。`fetch_url` 已纳入运行时工具注册表，协议、DNS、重定向和响应体限制均由专用测试覆盖。

# Agent / Harness Take-home（智能体方向）

## 背景

金融人工智能北京市重点实验室会使用 LLM 辅助研究、分析和日常工作。要让模型可靠地完成多步骤任务，除了模型本身，还需要程序管理上下文、调用工具、处理运行状态，并在适当环节允许人参与。

本题主要关注你能否构建一个小型、可运行的 Agent / Harness 原型。金融场景仅用于提供应用背景和功能测试语境；本题不考金融知识，不要求形成投资建议、交易信号或价格预测。

## 想解决的问题

请使用 Python 和基础 LLM API 调用，构建一个能够围绕用户给定任务，通过工具完成多步骤工作的 Agent / Harness。你需要自行决定系统如何组织、工具如何接入、何时继续或结束，以及如何处理需要人参与的情况。

本题没有唯一标准架构。我们希望看到一个真正运行的系统，而不是仅有 Prompt、静态演示、workflow 或一次模型调用的包装。

## 基本要求

提交的系统需要满足以下要求：

1. **自行实现 Agent 控制流**：程序能够根据模型响应决定继续调用模型、执行工具、等待人工介入或结束任务。
2. **支持工具使用**：至少能够描述、选择、调用工具，并将工具结果纳入后续处理；应考虑无效调用或工具失败等情况。
3. **体现真实异步处理**：在适合并发的环节使用 Python 异步能力，并能说明其行为。仅将同步流程改写为 `async` 函数，不足以体现异步执行。
4. **支持 Human-in-the-loop**：系统中需要存在人为介入机制，并妥善处理介入前后的任务状态。介入形式和具体交互由你自行设计。
5. **可运行、可检查**：提供清晰的启动方式、一次实际运行结果，以及可以帮助他人理解关键行为的测试或运行记录。

除上述要求外，Agent 的任务范围、工具设计、模块组织、状态保存方式、异步策略和人机交互方式均由你自行判断。可以使用本地或外部工具；请确保提交的项目能够在说明的环境中运行。

## 技术边界

- 使用 Python 实现。
- 使用基础 OpenAI-compatible LLM API 调用；可以使用相应的基础 API 客户端 SDK。
- 必须由你自己的项目代码掌握 Agent 的控制循环、工具执行编排和运行状态流转。下文所称 **Agent loop** 指应用根据模型响应和工具结果重复推进任务、直到达到完成或停止条件的循环；**Harness** 指围绕模型提供执行控制、工具接入、上下文/状态管理及必要运行边界的应用层。
- 不得使用已经封装 Agent loop、核心工具调度或 Harness 状态编排的现成 Agent 框架、SDK 或项目。判据：若某依赖替候选人实现 Agent loop、核心工具调度或 Harness 状态编排，则不得用于本题核心执行链。范围包括但不限于 DeepAgents、OpenAI Agents SDK、Pi Agent SDK、Claude Agent SDK、OpenCode SDK。以上举例仅为说明职责边界，不构成对任何产品的评价。不得通过换名、封装或委托给其他服务的方式规避此限制。
- LangChain、LangGraph 等通用 LLM/工作流框架不得承担本题核心执行链（包括模型循环、工具调度或状态编排）。基础 API 客户端及不接管上述核心控制流的普通辅助库可以使用。
- 如自行扩展，请确保核心要求仍由你自己的 Harness 控制。

请依据上文的职责判据判断依赖是否属于被禁止的 Agent/Harness 封装；请在 README 中列出依赖及其用途，并说明其是否参与核心执行链。
